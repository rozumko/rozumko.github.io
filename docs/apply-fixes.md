# Як застосувати виправлення у власному GitHub-репозиторії

Нижче наведено покрокову інструкцію, яка допоможе перенести виправлення з цієї гілки до вашого репозиторію GitHub.

## 1. Клонування або оновлення локального репозиторію
Якщо у вас ще немає локальної копії, виконайте:

```bash
git clone <URL_ВАШОГО_РЕПОЗИТОРІЮ>
cd <НАЗВА_КАТАЛОГУ>
```

Якщо копія вже є, просто перейдіть у каталог проекту й оновіть `main` (або `master`) гілку:

```bash
git checkout main
git pull origin main
```

## 2. Додавання віддаленого репозиторію з виправленнями
Додайте тимчасовий remote із цим репозиторієм (або форком, де є зміни):

```bash
git remote add fixes <URL_ДЕ_ЗНАХОДЯТЬСЯ_ВИПРАВЛЕННЯ>
# Якщо remote вже існує, оновіть його:
# git remote set-url fixes <URL_ДЕ_ЗНАХОДЯТЬСЯ_ВИПРАВЛЕННЯ>
```

Далі стягніть гілку з виправленнями:

```bash
git fetch fixes <НАЗВА_ГІЛКИ>
```

## 3. Застосування змін
Ви можете обрати один із двох підходів:

### Варіант A. Злиття (merge)

```bash
git checkout main
git merge fixes/<НАЗВА_ГІЛКИ>
```

### Варіант B. Перенесення комітів (cherry-pick)

Якщо потрібно забрати лише один чи кілька комітів:

```bash
git checkout main
git cherry-pick <SHA_КОМІТУ>
```

> Порада: перегляньте `git log fixes/<НАЗВА_ГІЛКИ>` щоб знайти потрібні SHA комітів.

## 4. Розв'язання конфліктів (за потреби)
Якщо виникли конфлікти:

1. Відкрийте файли з конфліктами, вручну виправте позначені ділянки.
2. Після виправлення додайте файли в індекс: `git add <файл>`.
3. Завершіть злиття або cherry-pick: `git commit` або `git cherry-pick --continue`.

## 5. Перевірка та тестування
Після застосування змін запустіть локально перевірки, які ви зазвичай використовуєте (наприклад, `npm test`, `npm run lint` чи інші команди).

## 6. Відправка змін у ваш репозиторій

```bash
git push origin main
```

За потреби створіть pull request, якщо працюєте через окрему гілку.
