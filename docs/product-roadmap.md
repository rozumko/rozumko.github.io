# Product Roadmap — РОЗУМКО

_Останнє оновлення: 2026-05-07_

## Product direction

РОЗУМКО має розвиватися як освітній хаб для учнів 1-4 класів:

- тренування обчислювального мислення;
- демо-олімпіада без коду;
- офіційні онлайн-олімпіади за кодом;
- матеріали, курси, корисні ресурси та ігри;
- кабінет вчителя для класів, реєстрацій, кодів і результатів.

Олімпіада є кульмінацією платформи, але не єдиним сценарієм. Дитина має
мати змогу тренуватися і пробувати формат без участі в офіційній події.

## Target user flows

### Admin

Адмін створює подію олімпіади:

- назва події;
- дата і час початку;
- дата і час завершення;
- статус: draft, published, active, finished, archived;
- для кожного класу: кількість питань, час, перелік конкретних питань;
- правило: у межах події питання не повторюються для одного класу.

Адмін також керує банком питань:

- клас 1-4;
- складність: easy, medium, hard;
- режим використання: тренування, демо, олімпіада;
- тип завдання;
- пояснення для тренування.

### Teacher

Вчитель реєструється на платформі, проходить авторизацію і працює з власним
кабінетом:

- створює класи;
- додає або готує учнів до участі в події без збереження зайвих персональних даних;
- реєструє клас або окремих учасників на подію;
- отримує персональні коди участі;
- у майбутньому отримує персональні посилання на оплату для батьків;
- переглядає результати своїх учасників;
- генерує сертифікати участі та дипломи.

Імена і прізвища дітей для сертифікатів та дипломів не зберігаються на сервері.
Вчитель вводить їх локально перед друком або PDF-експортом.

### Student

Учень має три окремі сценарії:

- тренування без коду: клас + складність, з поясненнями;
- демо-олімпіада без коду: складні питання відповідного класу, формат близький до олімпіади;
- основна олімпіада за кодом: офіційний результат, таймер, серверне оцінювання.

Демо-олімпіада не повинна вимагати код офіційної події. Код потрібен тільки
для офіційної участі.

## Demo olympiad decision

Демо-олімпіада має бути окремою кнопкою на сторінці учня і, можливо, на
головній сторінці.

Цілі демо:

- показати формат олімпіади;
- зняти страх перед офіційною участю;
- дати вчителю і батькам швидко оцінити якість завдань;
- не створювати офіційний результат;
- не вимагати реєстрацію або код.

Питання демо:

- беруться зі складного рівня для відповідного класу;
- не повинні розкривати ключі відповідей у браузер, якщо демо імітує
  олімпіадний режим;
- можуть не зберігати результат або зберігати лише анонімну технічну статистику.

## Privacy principles

РОЗУМКО має збирати мінімум даних про дітей.

Сервер може зберігати:

- код участі;
- подію;
- клас;
- статус спроби;
- відповіді;
- бал;
- час початку і завершення;
- технічні ідентифікатори.

Сервер не повинен зберігати:

- ім'я дитини;
- прізвище дитини;
- email або телефон дитини;
- дані батьків без окремої потреби;
- платіжні картки або інші платіжні секрети.

Для сертифікатів і дипломів:

- ПІБ вводить вчитель перед генерацією;
- генерація відбувається у браузері;
- ПІБ не надсилається на backend;
- ПІБ не записується у базу даних;
- повторна генерація вимагає повторного введення імені.

## Backup and recovery principles

Потрібні два рівні захисту:

1. Локальний аварійний backup під час проходження олімпіади, щоб учень не
   втрачав прогрес через збій браузера або мережі.
2. Регулярний backup PostgreSQL, щоб можна було відновити дані після помилки,
   збою провайдера або пошкодження БД.

Мінімальна ціль:

- регулярний `pg_dump`;
- зашифроване зберігання backup-файлів;
- retention policy;
- окремий тест відновлення;
- документація процедури restore.

Backup вважається робочим тільки після перевіреного відновлення на тестовій БД.

## Business model direction

Рекомендований порядок монетизації:

1. Платна участь в офіційній олімпіаді.
2. Після пілоту - платний доступ до розширених ресурсів і прогресу дитини.
3. Пізніше - мобільний застосунок або PWA для тренувань, матеріалів та ігор.

Офіційна олімпіада має залишатися доступною тільки на ноутбуках, десктопних
комп'ютерах або планшетах. Мобільний сценарій краще використовувати для
тренувань, хабу, матеріалів і повторення.

## Implementation phases

### Phase 1 — Stabilize current olympiad MVP

- Перевірити, що офіційна олімпіада не віддає ключі відповідей у браузер.
- Забезпечити серверне оцінювання для всіх типів питань, які підтримує UI.
- Синхронізувати документацію з поточною PostgreSQL/Drizzle архітектурою.
- Покращити обробку збоїв і повторного завершення спроби.
- Додати базові тести backend-маршрутів для кодів, спроб і оцінювання.

### Phase 2 — Events model

- Додати таблицю `olympiad_events`.
- Додати таблицю `event_questions`.
- Прив'язати `access_codes` до `event_id`.
- Фіксувати список питань конкретної спроби в `attempt_questions`.
- Додати адмінський CRUD подій.
- Дати адміну можливість обирати питання для кожного класу в межах події.

### Phase 3 — Demo olympiad without code

- Додати окрему кнопку "Демо-олімпіада" на сторінку учня.
- Додати endpoint для demo-питань без ключів відповідей.
- Визначити, чи демо рахується локально без збереження, чи через анонімну
  demo-спробу на сервері.
- Відокремити демо від офіційного коду участі.

### Phase 4 — Teacher classes and registrations

- Додати таблицю `teacher_classes`.
- Додати таблицю реєстрацій на подію без зберігання ПІБ учня.
- Дати вчителю можливість створювати класи.
- Дати вчителю можливість реєструвати учасників на подію.
- Генерувати персональні коди участі для зареєстрованих учасників.

### Phase 5 — Certificates and diplomas

- Додати генерацію сертифіката участі з результатів вчителя.
- Додати генерацію дипломів за критеріями події.
- ПІБ вводиться вчителем локально перед друком/PDF.
- ПІБ не надсилається на backend і не зберігається.

### Phase 6 — Free pilot

- Провести безкоштовне тестування з реальними вчителями й учнями.
- Зібрати помилки, UX-проблеми, фідбек щодо складності питань.
- Відкоригувати банк питань і сценарії входу.
- Підготувати публічну політику приватності для запуску оплат.

### Phase 7 — Payments

- Додати модель платежів без збереження платіжних секретів.
- Використовувати платіжного провайдера для карток і фіскальних/платіжних даних.
- На сервері зберігати тільки статус оплати, provider payment id і зв'язок з
  подією/реєстрацією.
- Додати персональні посилання на оплату для батьків.

### Phase 8 — Hub and subscription

- Оновити головну сторінку під модель хабу.
- Додати розділи ресурсів, ігор, курсів і тренувань.
- Додати прогрес дитини тільки там, де це можна зробити без надмірного збору
  персональних даних.
- Розглянути платний доступ до розширених матеріалів після появи достатньої
  цінності поза олімпіадою.

## Near-term concrete next steps

1. Оновити документацію: прибрати застарілі згадки Firestore як основного джерела.
2. Спроєктувати міграцію для `olympiad_events`, `event_questions`,
   `attempt_questions`.
3. Реалізувати backend для подій.
4. Реалізувати адмінську вкладку подій.
5. Винести демо-олімпіаду в окремий сценарій без коду.
6. Додати генерацію сертифікатів/дипломів без збереження ПІБ.
7. Описати і протестувати backup/restore процедуру.
