# Огляд коду застосунку

## Загальний огляд
- Основний клієнтський код організований модульно: робота з Firebase та аутентифікацією винесена в `services/firebase.js`, валідація та інтеграція reCAPTCHA — у `utils/validation.js`, а UI-хелпери та логіка тесту поділені на `ui/dom.js` і `features/*.js`. Головний модуль підключає ці частини й керує станом застосунку, що покращує читабельність і повторне використання коду.【F:script.js†L12-L120】【F:features/quiz.js†L1-L60】【F:ui/dom.js†L1-L66】【F:utils/validation.js†L1-L120】
- Передбачено офлайн-стратегію: результати зберігаються локально, а потім синхронізуються з Firestore, коли з'єднання відновлюється.【F:script.js†L139-L175】
- Для режиму «Іспит» реалізовано «lockdown»-поведінку з перевіркою fullscreen/visibility та автоматичним призупиненням таймера, що підвищує чесність тестування.【F:script.js†L440-L520】【F:features/timer.js†L1-L44】

## Критичні проблеми (блокують користувачів)
1. **Відсутні елементи інтерфейсу, з якими працює дашборд**. `updateDashboard()` очікує селектор класу (`#user-grade-selector`) і контейнер деталізації прогресу (`#progress-details-container`), але таких елементів немає в `index.html`. У результаті перша ж спроба звернутися до `gradeSelector.innerHTML` викликає помилку `Cannot read properties of null`, і дашборд не завантажується для жодного автентифікованого користувача.【F:script.js†L178-L220】【F:index.html†L80-L168】
2. **Форма реєстрації звертається до неіснуючого поля класу**. Обробник сабміту шукає `#register-grade` і одразу читає `.value`, але в розмітці форми відсутній будь-який селектор класу. Це призводить до миттєвого краху обробника ще до створення акаунта, а користувач бачить порожню форму без пояснень.【F:script.js†L526-L599】【F:index.html†L84-L105】
3. **Комбінації «клас + складність» переважно непридатні**. Модальне вікно пропонує 2–8 класи та три рівні складності, однак у репозиторії є лише файли для 2-го й 4-го класів, причому кожен містить по 1–2 питання на складність. Оскільки тест вимагає мінімум 5 питань одного рівня, більшість запусків завершуються повідомленням «недостатньо питань».【F:script.js†L266-L360】【F:script.js†L48-L305】【F:data/questions/math/grade2.js†L1-L17】
4. **reCAPTCHA-токени не використовуються**. Кожен обробник входу/реєстрації очікує токен reCAPTCHA, але далі він ніде не передається — ні на бекенд, ні в Firebase Custom Claims. Це даремне виконання reCAPTCHA, що сповільнює форми без реального захисту від ботів.【F:script.js†L576-L644】

## Додаткові спостереження
- Нові акаунти Google Sign-In отримують жорстко заданий `currentGrade: 4`; варто дозволити користувачеві обрати клас під час першого входу, щоби дані прогресу відповідали очікуванням.【F:script.js†L120-L132】
- Модуль `RecaptchaService` завантажує скрипт і повертає токени, але не обробляє сценарій, коли виконання заблоковано політиками браузера. Можна додати відображення повідомлення користувачу при відмові від reCAPTCHA.【F:utils/validation.js†L93-L175】

## Рекомендовані кроки
1. Додати в розмітку відсутні елементи (`<select id="user-grade-selector">`, контейнер прогресу тощо) або адаптувати `updateDashboard()` до фактичної структури DOM.
2. Розширити форму реєстрації полем вибору класу (з валідацією) або оновити логіку реєстрації, щоб вона не вимагала `#register-grade`.
3. Узгодити перелік доступних класів/складностей із реальною базою питань або поповнити банк питань так, щоб кожна комбінація мала принаймні 5 питань.
4. Вирішити, як використовувати reCAPTCHA-токени (наприклад, відправляти їх до Cloud Function для валідації) або тимчасово вимкнути reCAPTCHA, щоб не вводити користувачів в оману.
